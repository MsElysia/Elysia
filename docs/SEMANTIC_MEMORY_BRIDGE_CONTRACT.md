## Minimal compatible future contract (proposal, no production change)

Retain elysia.local-context.v1, original evidence source_id/chunk_id/revision/source_sha256 and existing bounds. Add optional per-evidence `recall_reasons` list with typed reasons (lexical, canonical_tag, approved_alias, related_tag, project_relation, vector), stable IDs and source-link verification, not generated explanations as facts. Existing matched_tokens stays compatible and may be empty for legitimate tag-only recall. Preserve trust, current revision, original text/hash and verified expansion pointer. Never infer permission from evidence. On unresolved project ambiguity retain distinct evidence with explicit clarification-needed state, don't synthesize a single answer. Keep no_memory_support true when absent. Ranking must preserve current revision and project scope before budget selection; no alias collision or repeated statement voting. Keep source hash separate from excerpt hash.

Compact registry (conceptual, no second store/schema in A): stable ID 17 -> finish_choice, aliases coating/finish choice; ID 42 -> fictional project Larkspur. A verified chunk may point to [17,42], and ID17 may link many chunks, each link independent with source_chunk_id, source revision/hash, selected/candidate state, method, rule/model/prompt version, confidence. IDs never reused; normalize aliases and require approval before candidate participates; corrected records cannot remain authoritative just because an old link exists. No private-text transmission, no mapping leakage, no promotion by repetition. Historical #97 normalized string decisions provide a basis, not a proved numeric registry.
